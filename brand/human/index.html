01 — the brand

The whole thing, on one screen

Write your component once. It compiles to real, idiomatic framework code — and the outputs are proven to behave the same in a real browser.

Frameless is a naturalist's field guide, not a tech brand.

Stickers are how you mark that you were actually there. A park sticker is a small proof of presence — not an advertisement, a receipt.

Canonical order: React, Vue, Svelte, Solid, Angular, Qwik. It opens on the most recognised and closes on the one that makes the technical point. Keep this order in badges, tables, nav and prose.

Never total them up. Do not write "Ship six", "One source. Six outputs.", "six frameworks", or any variant that turns the promise into an inventory.

saturated fill (glossy, lighter at top-left) -> keyline in the dark end of that hue -> band tinted to that hue -> drop shadow -> about -3deg of tilt

The framework name is set in white INSIDE the sticker, always. Not a tooltip, not a caption. A word is the only treatment that survives a crop, a grayscale conversion and a screenshot with no alt text.

The three-beat explainer

1

Write it once.

One component, in .tsrx. State, markup, composition — the parts you'd write anyway.

2

Compile it out.

Frameless compiles to a semantic representation first, then emits per framework. Each target gets code that reads like it was written for that framework, because it was.

3

Prove it matches.

Every build diffs behavior across every target in a real browser. The checker is itself mutation-tested, so a pass actually means something.

Lines that are always wrong

  • "Zero runtime." → use "No Frameless runtime." The output still needs the framework's
  • "Guaranteed identical output." → behavior is verified identical; the output is
  • "Replaces your framework." → it emits into frameworks and depends on them being good.

Frameless Studio is not out

Frameless Studio — coming soon — See your components in every state, in every framework you compile to. A simpler Storybook that works wherever your code does.. Never imply availability, never manufacture urgency.

02 — depth

Every die-cut object casts a real shadow. Elevation is the brand.

fill -> tinted dark keyline -> thick band (6-8% of width) -> drop shadow

The most defining quality of the concept art is depth — the wordmark and all six badges sit above the page on a heavy offset shadow. The previous version of this kit BANNED box-shadow kit-wide, having measured four flat vector PNGs and generalised from them. That deleted the one thing the art is most recognisable for.

Both are stacked drop-shadow() filters, so the shadow follows the die-cut silhouette rather than the bounding box. Never a box-shadow.

The primitive

Usefilter: drop-shadow() EVERYWHERE. box-shadow casts a shadow of the element's BOX — a rounded rectangle behind a die-cut shape, which instantly kills the illusion. drop-shadow() follows the actual alpha silhouette: the cut edge, the lettering, the wobble of the band. Stack two of them (a hard offset plus a soft ambient) for the register the concept art's wordmark reads in.
NeverUse filter: drop-shadow() instead, everywhere except --elev-inset. A filter follows the alpha silhouette; a box-shadow follows the border box, which is wrong for every die-cut object in this kit.
NeverA die-cut object with no shadow. Elevation is mandatory — it is the quality the concept art is most recognisable for.

Where it goes, and what it costs

OnOn the element that owns the alpha — the PNG, the SVG, or the outermost die-cut wrapper. A filter on a parent shadows the whole subtree as ONE silhouette, which is right for a sticker and never right for a text block.
WatchA non-none filter creates a stacking context AND a containing block for fixed/absolute descendants. A position: fixed child of a filtered element is fixed to that element, not to the viewport — this matters for any slide-in panel.

Texture — the bed is never a flat fill

The page bed is NEVER a flat fill. A fine noise grain is applied globally, with an optional faint ruled grid. See ./elevation.css.

The grain is a self-contained data: URI, which is the only form of image guaranteed to work when the kit is opened from file://: ✓ self-contained. It is applied to body by agent/visual/colors_and_type.css, so a page that links the entry stylesheet has grain without asking. Strength 0.055, or 0.10 on small saturated objects where the default disappears. The ruled grid is on a 48px pitch and belongs to section beds and empty space, never under reading copy.

03 — colour

28 permitted pairs, 18 forbidden ones, and 17 tokens

Saturated, cool, physical. Vivid die-cut stickers with a real drop shadow, laid on a dark textured bed. Colour is used in confident blocks — never desaturated, never aged.

The kit defaults to the DARK bed. Saturated colour needs a dark ground to read as lit, all three named references (avara.xyz, react.gg, sticker.oooo.so) are dark, and lime display type is only legal on dark. A light paper island is available with [data-surface="light"] for reading-length copy.

#ffffff is FORBIDDEN as a page bed. It is permitted INSIDE a saturated framework sticker, where it is the name label and carries a measured ratio against that fill.

Real pixels, sampled in Chromium by drawing the concept art to a canvas and reading getImageData. Two statistics per region: the block average (what a naive sample gives, and what gets pulled toward the cream band and the paper grain) and the mean of the top 5% most saturated pixels (what the fill actually is). Every framework fill below is anchored on the SATURATED statistic — anchoring on the block average is the exact error that produced the rejected first attempt.

The surface flip

Put [data-surface="light"] on a region for the light paper island; [data-surface="deep"] switches back. The role tokens flip as a SET.

Flipping one at a time is how the dark-bed cream ink ends up on the light paper at 1.1:1 — invisible, and the single most expensive mistake available. Both failure directions are listed in forbidden_pairs so the gate proves they are real.

Does not flip: --band, --keyline, --accent, --accent-ink, every value under framework_colors. They are printed ink and printed paper, not roles. A die-cut band is the same cream on any bed, and a React sticker is the same blue on any bed. That is what makes a sticker a physical object rather than a themed div.

03a — the one rule that generalises

The lime law

Lime is a surface, a mark and a display voice. Never an ink on light.

#cce007 has a relative luminance of 0.6616 — it is a LIGHT colour that behaves like a highlighter. It cannot carry reading copy on any light bed, at any size, in any weight.

This rule survived the rebuild intact. It was never a taste call: lime on light genuinely fails, and it fails by a factor of three. What changed around it is that the kit now defaults to a dark bed, so the surface where lime is legal is the common case rather than the exception.

body_text_on_light
NEVER. Any light surface, any size, any weight.
body_text_on_dark
Avoid. Legal by ratio, wrong by role — reading copy is --ink cream. Lime is for display and for marks.
display_text
Legal on --surface (dark) at 12.41:1, at --step-3 or larger. This is where the hero headline lives.
button_fill
Primary CTA = lime fill + --accent-ink label (13.08:1). The flagship usage of the colour.
the_wordmark
The lime wordmark fill is a FILL, not type in the accessibility sense — it is ringed by a black keyline and a cream band and carries a drop shadow, and its accessible name comes from the surrounding markup. Do not "fix" its contrast by changing the fill.
framework_marks
A framework logo may NEVER render in --accent. Marks render in that project's own brand colours, in white, or as the grey silhouette used for the deselected carousel state. Nothing else.

03b — measured, not asserted

Every pair, with its real ratio

Computed rather than transcribed: WCAG 2.x relative luminance; channel = c <= 0.03928 ? c/12.92 : ((c+0.055)/1.055)^2.4; L = 0.2126R + 0.7152G + 0.0722B; ratio = (Lmax+0.05)/(Lmin+0.05)

AA normal text is 4.5, large text is 3, non-text is 3. --step-2 and above clears the WCAG large-text threshold at every viewport in the shipped Utopia scale, so size gating is expressed as a TOKEN and stays checkable.

This page will not set type in a pairing whose recomputed ratio fails AA normal text, and it will not set type in lime at all. Those rows show a fill bar instead of a word. Both rules are applied by recomputing at build time rather than by remembering, which is why a demonstration of a forbidden pairing cannot accidentally become an instance of one. Lime clears AAA on the dark bed, but a specimen is set at --step--1 and lime type is legal only at --step-3 or larger: its display specimen is the law's own statement in the section above.

06 — the die-cut vocabulary

Printed, cut, and sitting above the page

A sticker is a printed thing, cut out of a band of paper and laid on a dark textured bed. Four things make it read as an object, and dropping any one of them stops it being a sticker: the band, the keyline, the tilt, and the shadow.

TokenValueWhat it is
--sticker-band-ratio0.07The band as a proportion of the object's width: 7.0%, the midpoint of the 6–8% measured on real die-cut stickers. Kept as a raw ratio so a canvas or SVG renderer can apply the same rule outside CSS.
--sticker-bandclamp(0.5rem, 7cqw, 2rem)The same rule in CSS. cqw is "a percent of the container's width", so this expresses the measurement rather than approximating it. Needs container-type: inline-size on an ancestor — an element cannot query itself.
--sticker-band-fixed0.7remFor anywhere container units are unavailable. Not a lesser option — it is the right answer on a button.
--sticker-keyline2pxThe default die-cut stroke. It equals --focus-width, which is what makes a focused die-cut component shift by zero pixels. It is also the boundary that survives forced-colours mode, where the shadow is dropped by the OS.
--sticker-keyline-bold3pxLarge display die-cuts only. On a button it reads as a mistake.
--sticker-keyline-heavy4pxThe selected carousel sticker at roughly 2×, and nothing smaller.
--sticker-keyline-hair1pxDividers and inner rules. Never a die-cut boundary — that is the whole distinction.
--sticker-radius1.25remA die-cut never has a sharp corner: the blade has a radius and the paper tears if it does not.
--tilt-rest-3degDeclared in ../tokens/sticker.css, restated here because motion returns to it. The rest value is -3deg, measured off Sticker Forge's own overall-tilt slider rather than guessed. The four values are deliberately unequal and deliberately not mirrored so a group looks placed by hand. Cycle them across siblings; do not invent a fifth. A decorative sticker at 0deg reads as a div.

The wordmark applies the same rules with the letterform as the die-cut object, so the basis is its ink height: 72.75 at 100px, measured off the shipped WOFF2 by build-wordmark.mjs rather than assumed. Band 0.115, keyline 0.09, shadow offset 0.018 / 0.085 of that height. The shadow is the fourth layer and it is not optional. A lockup drawn without it is not this wordmark.

07 — motion

6 curves. Six named curves. If a motion does not fit one of them, the motion is wrong, not the vocabulary.

A sticker is a physical object on paper. It presses down instantly and comes back up gently, because that is what a thumb and a piece of vinyl actually do. Every curve here is asymmetric or springy for a physical reason, never because a designer liked the shape.

press

cubic-bezier(0.4, 0, 1, 1)
90ms

Pressing a sticker down is instant.

Ease-in with no deceleration: it starts moving and never slows, so the motion ends at full speed the way contact does. 90ms is below the threshold where a press reads as laggy.

release

cubic-bezier(0, 0, 0.2, 1)
160ms

Deliberately asymmetric with press — down fast, up gentle.

The asymmetry IS the design. A press and release that share one curve feels like a state toggle; a fast press and a slow release feels like a finger lifting off vinyl. If you find yourself using one curve for both directions, you have removed the point.

peel

cubic-bezier(0.34, 1.56, 0.64, 1)
260ms

Overshoot = a physical object with springiness.

The second control point sits above 1, so the value passes its target and comes back. That overshoot is the only place in the system where something behaves elastically, and it is reserved for the one gesture that is literally physical: a die-cut corner lifting off the page.

slide

cubic-bezier(0.65, 0, 0.35, 1)
300ms

Output-switcher; A to B swaps.

Symmetric ease-in-out. A swap has no privileged direction — going from React to Solid should feel exactly like going back — so the curve is its own mirror. This is the curve the six-output switcher runs on, which makes it the most-seen motion in the brand.

settle

cubic-bezier(0.22, 1, 0.36, 1)
420ms

Long tail, no overshoot — it settles, it does not bounce twice.

Reaches most of the distance early and then takes a long time to arrive. Used for things that come to rest: a panel arriving, a sticker being placed. Distinct from peel because it never passes its target — a settling object that bounces reads as a bug.

instant

linear
0ms

prefers-reduced-motion fallback.

Not a design choice — the escape hatch. Every other curve collapses to this one when the user has asked for reduced motion, which is why it is in the vocabulary rather than being an absence of one.

Transforms

TokenValueState
--transform-peelrotate(-1.5deg) translateY(-3px) scale(1.015)The lifted state. A corner physically off the page.
--transform-presstranslateY(1px) scale(0.985)The pressed state. A thumb on the sticker.
--transform-restnoneThe resting state. Not an animation — where a sticker lives.

Reduced motion is mandatory

Under (prefers-reduced-motion: reduce) every duration collapses to 0ms, every easing becomes linear, every transform token becomes none, and the only motion left is an opacity fade capped at 120ms.

Vestibular triggers are movement, not change. Removing transform and collapsing duration removes the trigger; a short opacity fade does not reintroduce it and keeps state changes from being jarringly abrupt. 120ms is the ceiling, not a target.

The tilts and the shadows stay. A resting rotation is where a sticker lives, and elevation is not motion. What must not happen is the peel transform, which is a movement.

Hard rules

  • Shadows are REQUIRED, and they are filter: drop-shadow(), never box-shadow. A box-shadow casts the element's BOX, and a rounded rectangle behind a die-cut shape kills the illusion. The elevation scale is --elev-sticker / --elev-card / --elev-lifted in ../tokens/elevation.css; motion transitions BETWEEN those steps rather than inventing shadows of its own.
  • prefers-reduced-motion: reduce is mandatory, not optional. Under it every duration collapses to 0ms, every transform token becomes none, and the only motion permitted is an opacity fade capped at 120ms.
  • Decorative stickers are never at 0deg at rest. The constant rest tilt is -3deg (Sticker Forge's own default), varied per instance across --tilt-1 to --tilt-4.
  • Do not invent a seventh curve. Six is the whole vocabulary.

08 — voice

Precision as personality

A careful engineer who has done the work, is quietly certain, and refuses to overstate by even one word.

Banned outright: blazing-fast, powerful, seamless, effortless, revolutionary, game-changing, next-generation, cutting-edge, robust, world-class, magical.

Say the promise plainly. Never count.

WRONG"Ship six." / "One source. Six outputs." / "Six targets, all verified."
RIGHT"Compile once, output anywhere."

Show the receipt

WRONG"Rigorously tested for correctness."
RIGHT"Behavior diffed across every target, in a real browser, on every build."
WRONG"Our equivalence checking is thorough."
RIGHT"We mutation-test the checker. An oracle that cannot fail is not evidence."

Verbs over adjectives

WRONG"A powerful, modern, blazing-fast compiler."
RIGHT"It compiles one file. It emits framework-native code. It proves they match."

Short sentences carry the weight

RIGHT"Most frameworks hydrate. Qwik resumes. Same source. Same behavior. Proven."

Precision about what is and isn't identical

WRONG"Identical output across every framework."
RIGHT"Different output for every framework. Identical behavior. That's the point."

Own the corrections out loud

WRONG(silence about past mistakes)
RIGHT"We once shipped a broken test harness and it told us Qwik didn't work. It did. The harness was wrong. That's in the log."

Dry humor, never zany

WRONG"Frameworks hate this one weird trick!"
RIGHT"Write once, run anywhere has been promised since 1995. This time there's a test suite."

Second person, present tense

WRONG"Developers can leverage Frameless to enable multi-framework workflows."
RIGHT"You write one component. You ship it anywhere."

Never bury the reader in the compiler

WRONG"Frameless lowers .tsrx to a semantic IR and emits per-target."
RIGHT"You maintain one component instead of six. It compiles to a semantic representation first, so each framework gets idiomatic code rather than a translation."

Concede the case where the tool isn't the answer

RIGHT"Shipping to one framework? Write the framework code."
