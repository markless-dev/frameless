Frameless component · the one interaction

framework-carousel

Pick a framework and read what it actually compiled to. The row slides beneath a fixed focal point, everything unselected goes grey, and the panel carries the real file.

Use it when

  • You have one interaction to spend. Spend it here.
  • The claim is "the output is code your team would have written" and a reader should be able to check.
  • You want breadth to be navigable rather than listed.

Don't use it when

  • You do not have real emitted files to show. Do not fabricate output.
  • You want a logo wall. That is framework-badge.
  • You were going to autoplay it. Nothing in this kit moves on its own.

Live

Click a sticker, or focus the row and use ← → Home End. The row moves; the focal point does not.

// @generated by @frameless/react; do not edit.
import { useRef, useState } from 'react';

export function RenderOnce({ label, multiplier, visible, onTrace }) {
	const setupDone = useRef(null);
	if (setupDone.current === null) {
		setupDone.current = true;
		onTrace('setup', { runs: 1 });
	}
	const [count, setCount] = useState(1);
	const [prefix] = useState(() => `${label}:`);
	const derived = `${prefix}${count * multiplier}`;
	return (
		<div data-s1-root="">
			{!visible ? (
				<p data-branch="hidden">hidden</p>
			) : (
				<section data-scenario="s1">
					<output data-value="derived">{derived}</output>
					<button
						data-action="increment"
						onClick={() => {
							const nextCount = count + 1;
							setCount(nextCount);
							onTrace('change', { count: nextCount });
						}}
					>
						increment
					</button>
				</section>
			)}
		</div>
	);
}

// @generated by @frameless/solid; do not edit.
import { createSignal, untrack, Show } from 'solid-js';

export function RenderOnce(props) {
	untrack(() => props.onTrace('setup', { runs: 1 }));
	const [count, setCount] = createSignal(1);
	const prefix = untrack(() => `${props.label}:`);
	const derived = () => `${prefix}${count() * props.multiplier}`;
	return (
		<div data-s1-root="">
			<Show
				when={!props.visible}
				fallback={
					<section data-scenario="s1">

						<button
							data-action="increment"
							onClick={() => {
								setCount(count() + 1);
								props.onTrace('change', { count: count() });
							}}

							increment
						</button>
					</section>
				}
			>
				<p data-branch="hidden">hidden</p>
			</Show>

Keyboard

KeyDoes
← / →Move selection. The row slides; the focal point stays put.
Home / EndFirst / last framework.
TabEnters the row ONCE and lands on the selected sticker — roving tabindex. Six stops in a row would make the rest of the page unreachable for anyone tabbing through it.
EscCloses the panel.

The row is a tablist and the panel is its tabpanel, because that is exactly what this is: one row of choices, one region that changes with them. Arrow-key selection inside a tablist is the expected behaviour rather than an invention.

Reduced motion

The scale and the desaturation stay — they are states, not movement, and they are the whole selection language. What goes is the travel: the row jumps to position and the panel appears rather than sliding.
