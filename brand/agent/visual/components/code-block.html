code-block

The product is code, so this is where the argument lands. Monospace, one colour, and a marked line instead of a rainbow.

Use it when

  • Showing a .tsrx source or a real emitted output.
  • A terminal transcript, a file path, a diff.
  • You want to point at one line — mark it, don't colour the tokens around it.

Don't use it when

  • It is inline code in a sentence. Use <code>.
  • You are about to set it in Que Grotesque. It is not a monospace.
  • You want syntax colours. There is no highlighting palette in this kit, on purpose.

Why there is no syntax highlighting

  1. A highlighting theme is a second colour system. It drifts from the real one immediately and nobody notices.
  2. This kit has one ink and one secondary ink. A five-colour highlighter cannot be built from them without inventing values, and inventing values is the failure mode the whole token system exists to prevent.
  3. What matters on a Frameless page is "these two outputs differ HERE". A marked line states that precisely. A rainbow does not.

If a product surface genuinely needs highlighting, ship it behind its own stylesheet and keep it out of the brand kit.
