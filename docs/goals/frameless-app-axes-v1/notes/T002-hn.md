## 3. The three refusals, verbatim, and how each was narrowed

The card predicted none of these. Each was hit on a real emit attempt.

### 3.1 An element with a handler may not sit beside text — THREE LANES AT ONCE

The subtext first read `<span class="hn-score">{story.points}</span>{story.pointsLabel}`
with the `unvote` and `hide` buttons as later siblings of those dynamic texts. **react,
solid and qwik took it.** The other three refused:

```
svelte:  Svelte emitter cannot inline <button>: it sits beside text and needs a
         multi-line start tag
vue:     Vue emitter cannot inline <button>: it sits in a text-bearing run and needs
         a multi-line start tag
angular: Angular emitter cannot inline <button>: it sits in a text-bearing run and
         needs a multi-line start tag
```

Mechanism, read off all three emitters and identical in each: a parent with **any** text
child prints its children inline (`hasTextChild` in svelte, `!children.every(isBlockLevel)`
in vue and angular), and an inline host whose start tag does not fit on one line is refused
rather than printed with newlines that would change what the page renders. **A handler
attribute is always multi-line.**

**NARROWED, NO EMITTER TOUCHED:** every text run got its own `<span>`, which makes the
parent's children all hosts, which un-inlines them.

### 3.2 A `<form>` with `submit` and no `click` is a Svelte over-fire

```
Emitted Svelte module HnFront.svelte suppresses [a11y_click_events_have_key_events,
a11y_no_noninteractive_element_interactions] but without those annotations Svelte
reports []. A suppression that changes nothing is a silent over-fire.
```

That emitter suppresses both codes at **every** `<form>` carrying an event
(`A11Y_EVENT_HOST_TAGS = new Set(['form'])`), then `assertCompilesClean` proves the
suppression fires in **both** directions. S10, S11 and S12 all happen to carry a `press`
trace on their forms, so **no earlier fixture had ever reached this**.

**NARROWED:** the footer search form now carries the same `press` trace the other three
applications carry. That is the corpus idiom, not a workaround — `press` is a real
observation channel.

### 3.3 `href="#"` is refused by the svelte gate

`a11y_invalid_attribute`. Every inert link is spelled `href="#/..."`, the form S10's
filter links already proved. Anticipated from S10 rather than hit here, and recorded
because a reader writing the item page (T003) will reach for `href="#"` first.

### 6.1 THE FINDING THAT MATTERED: the six lanes were rendering two different pages

With identical markup, identical CSS and every computed style equal, `/hn` rendered
**differently in two groups**:

| | qwik / svelte / angular | react / solid / vue |
|---|---|---|
| `.hn-page` rect | x=96, w=1088 | x=162, w=955 |
| story row height | 16px | **26px** |
| "More" link | left, under the titles | **centred** |

The cause is the **create-vite scaffold shell**, not the emitted output:
`:root { font: 18px/145% system-ui; letter-spacing: 0.18px }` and
`#root / #app { width: 1126px; text-align: center; display: flex }`. The root
`line-height: 145%` computes to 26.1px and is inherited as a **length**; `.hn-page`'s
`85%` resolved against 1126px instead of the viewport; `text-align: center` moved "More".

Neutralised **inside `hn.css`**, which is linked only by `/hn`, so the repair is scoped to
this page and touches nothing the three-way contract compares. Even after that the six
still disagreed by **10px on a 53-character headline** — `letter-spacing: 0.18px` × 53 =
9.5px, with `text-rendering: optimizeLegibility` on the same declaration. Both reset.

**Result: all six lanes now agree to the PIXEL** on `.hn-page`, `.hn-head`, `.hn-logo`,
the rank, the arrow, the title, the domain, the subtext, "More", the footer and the search
box — and on the rendered **text width**, which is the part that had still been wrong.

> **NOT REPAIRED, AND WORTH A CARD:** `/todomvc`, `/todomvc-advanced` and `/codex` are
> served by the same three shells and are presumably also 26px-line-height and centred in
> react, solid and vue while the other three lanes are not. That was not measured here.
> Nobody had compared geometry across all six lanes before.

### 6.2 Where this page is deliberately NOT the reference

- **The `|` separators are elements, not text.** The reference serves literal `" | "`
  text nodes; Angular's `escapeText` refuses a text node whose own edges are whitespace
  and the Vue gate rejects the emitted result. Sixteen of the template's sixty-two hosts
  are `<span class="hn-bar">|</span>` for that reason alone. Invisible on the rendered
  page.
- **Spacing is flex `gap`, never emitted formatting whitespace.** The six emitters print
  sibling elements with different inter-element whitespace (JSX drops it,
  `@vue/compiler-sfc` condenses it, Angular removes it, Svelte keeps it), so any layout
  leaning on it would render differently per lane. A flex container discards
  whitespace-only boxes in every engine. §6.1's pixel agreement is the proof.
- **`past`, `comments`, `ask`, `show`, `jobs`, `submit` are INERT.** `.tsrx` has no
  routing construct at all; three host routes would mean three instances with independent
  state.
- **The footer search FILTERS IN PLACE** rather than handing the query to Algolia, for
  the same reason. Ranks keep their seeded numbers while filtered, so a search shows
  `5.` and `10.` where the reference would renumber. Recorded, not hidden.
- **One seeded story has 1 point**, which a real front page would not. It is the only way
  the `point`/`points` flip is reachable — unvote is offered only after a vote.

## 8. What the dispatch did not know

### 8.1 "Relative times MUST ARRIVE AS PROPS" is not achievable, and does not need to be

The card says relative times must arrive as props because angular cannot name `Date`. The
first half of that reasoning is right and the instruction is wrong: **an age is per-row**,
and IR-8 has **no lowering for `TSArrayType`** — react, svelte and angular each throw
`has no IR-8 lowering for the type node TSArrayType`. There is no prop shape that can
carry twelve ages, which is exactly why S10, S11 and S12 all seed their lists in-component.

The spelling that works is the one S12 constraint (12) already chose for chat stamps:
**the ages are literal strings in the seeded data.** Nothing in the module names a global,
angular emits, and the fixture records both the constraint and why the prop route is
closed.

### 8.2 The card predicted no refusals; there were three, and two were new to the corpus

§3. The inline-beside-text rule (§3.1) is the interesting one: it is enforced by **three
emitters with three near-identical messages** and it means the reference's own subtext
markup is unauthorable here. The Svelte form over-fire (§3.2) had been latent since S10 —
three applications carried a `press` trace by coincidence and hid it.

### 8.3 The six lanes were not rendering the same page, and no card had ever checked

§6.1. Every static gate, every computed-style check and every body hash was consistent
with six identical pages. Only `getBoundingClientRect()` across all six at once showed
two groups. **This is the third instance of the rule the charter states** — a control
that is clickable but not drawn, a 3614-pixel heading divergence, and now a whole page
rendered at two different widths and two different line heights.

### 8.4 Two smaller ones

- **`pnpm demo`'s port preflight earned its keep again.** It moved qwik off 5175 and both
  vue and angular off 5178 without killing anything, and reported the holders. Both
  foreign PIDs (**64413** since Jul 27, **24931** since Jul 30 15:55) were verified alive
  and still listening at the end. `pkill -f` was never used; the runner was stopped by
  recorded PID (`79334`, then `89279`).
- **`git diff --exit-code` is blind to this entire card.** All 19 artifacts are untracked.
  Paired with `git status --short`, as the charter requires.

## 10. For T003 (the HN item page)

- The story shape is reusable: seed in-component, ages as literal strings, `hidden` for
  filtering, `<span class="hn-bar">|</span>` for separators, flex `gap` for spacing.
- **`hn.css` already carries the masthead, the page frame and the footer.** The item page
  should link the same sheet and add its own indent rules rather than restyle the shell.
- **Read §3.1 before writing the comment tree.** A comment's `reply` control beside its
  text is exactly the shape three lanes refuse.
- The shell neutralisation in `hn.css` (`:root`, `#root`, `#app`) is what makes six lanes
  comparable. Any new page-scoped sheet needs the same block or it will inherit
  `18px/145%` and `letter-spacing: 0.18px` in three of six lanes.
